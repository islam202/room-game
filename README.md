# خطفها

لعبة سرعة ورد فعل بالمصري بـ React 18 وVite. فيها لعب على جهاز واحد، ومطابقة عشوائية، وغرف أونلاين للأصحاب. المطابقة بتستخدم خادم Node.js وSocket.IO لتجميع لاعبين، وبعدها الجولة نفسها بتتنقل مباشرة بين المتصفحات باستخدام PeerJS/WebRTC.

## خطة التنفيذ في ١٠ سطور

1. إعداد React 18 وVite وTailwind CSS.
2. فصل قواعد الجولة المحلية في reducer مستقل.
3. تجهيز ١٥٠ سؤالًا، منها ٣٠ سؤالًا للرياضة و٣٠ للمعلومات العامة و٣٠ للفن في `src/questions.js`.
4. إضافة شاشة بداية وإعداد أسماء اللاعبين.
5. جعل وقت السؤال الافتراضي ١٢ ثانية، مع اختيارات من ٨ لـ٢٠ ثانية.
6. تسجيل إجابات الجهاز الواحد بـ Pointer Events و`performance.now()`.
7. إنشاء غرف بكود ٤ أرقام مع اختيار قسم الأسئلة وعددها ورابط دعوة قابل للإرسال.
8. ربط الماستر واللاعبين عبر PeerJS وWebRTC.
9. مزامنة الجولة والنقاط من الماستر، وترتيب الإجابات حسب وقت وصولها عنده.
10. تجهيز PWA والنشر كملفات ثابتة.

## التشغيل

محتاج Node.js وnpm على جهاز التطوير بس:

```bash
npm install
npm run dev
```

افتح `http://localhost:5174/` للنسخة المحلية. المنفذ 5173 مستخدم عندك لمشروع آخر؛ لذلك اللعبة تفتح على 5174. افتح العنوان كما يظهر في التيرمنال، وما تضيفش `/room-game/` في وضع التطوير. اللعب على جهاز واحد مش محتاج إعدادات خارجية. للغرف الخاصة اضغط «العب مع أصحابك»، اكتب اسمك، واعمل غرفة أو ادخل بكودها.

لتشغيل المطابقة العشوائية محليًا، شغّل الخادم في نافذة Terminal تانية:

```bash
npm run dev:server
```

بعدها افتح التطبيق كالمعتاد بـ `npm run dev`. التطبيق بيستخدم `http://localhost:3001` للمطابقة في وضع التطوير. المطابقة بتدور ١٥ ثانية؛ لو مفيش لاعب تاني، الجولة بتبدأ تلقائيًا مع الكمبيوتر. محتاجين إنترنت عشان PeerJS/WebRTC يوصّل الأجهزة.

## وقت اللعب والنقاط

- من ٢ لـ٦ لاعبين، وأسماء مستعارة لحد ١٢ حرف. في الغرف الخاصة، الماستر يختار بين الرياضة أو المعلومات العامة أو الفن، ويحدد ١٠ أو ٢٠ أو ٣٠ سؤالًا من القسم. المطابقة العشوائية واللعب المحلي يظلان على ١٠ أسئلة متنوعة.
- الوقت الافتراضي ١٢ ثانية للسؤال. الماستر يقدر يختار ٨ أو ١٢ أو ١٥ أو ٢٠ ثانية قبل فتح الغرفة، والوضع المحلي فيه نفس الاختيارات.
- الصح بالترتيب: ١٠ نقاط للأسرع، ثم ٦، ثم ٤، وبعدها ٢ لكل إجابة صح. الغلط يخصم ٣ نقاط ويقفل اللاعب في السؤال.
- في اللعب المحلي التوقيت مبني على `performance.now()`. أونلاين، الماستر بيسجل وقت وصول كل إجابة بساعته الرتيبة ويحسب النقاط.
- حالة الجولة مش بتتحفظ في `localStorage`؛ أسماء لاعبي الجهاز الواحد وإعداد كتم الصوت بس.

## إزاي الغرف الأونلاين والمطابقة شغالة؟

- الماستر بيحجز Peer ID مكوّن من بادئة اللعبة وكود ٤ أرقام من خادم PeerJS العام، واللاعب يدخل باستخدام الكود أو اللينك.
- إعدادات القسم وعدد الأسئلة بتتزامن مع كل اللاعبين، وبتظهر لوحة ترتيب ونقاط بجانب السؤال أثناء الجولة.
- بيانات اللعبة بتتنقل مباشرة بين أجهزة اللاعبين بتقنية WebRTC. PeerJS العام دوره خادم إشارات لتوصيل الأجهزة ببعض، مش خادم جولات أو قاعدة بيانات.
- الماستر هو اللي يوزع الأسئلة ويحسب النتيجة ويبعت تحديثات الجولة لباقي اللاعبين.
- المطابقة العشوائية بتحط اللاعب في طابور مؤقت داخل خادم Socket.IO؛ أول لاعبين بيتقابلوا بيتوصلوا، والماستر يبدأ الجولة تلقائيًا. لو الطابور فاضي بعد ١٥ ثانية، اللاعب يبدأ مع الكمبيوتر. الطابور في ذاكرة الخادم وبيتصفّر عند إعادة تشغيله.
- خادم المطابقة ما بيستقبلش الأسئلة أو الإجابات؛ بعد ما يتقابل اللاعبان، بيانات الجولة تفضل مباشرة عبر PeerJS/WebRTC زي الغرف الخاصة.
- مفيش Firebase Server Timestamp في النسخة دي. الترتيب حسب وقت وصول الإجابة عند الماستر؛ سرعة الشبكة ممكن تأثر على مين يتسجل الأول، ومفيش تحقق موثوق من ساعة كل لاعب.
- الاتصال المباشر ممكن يفشل على بعض الشبكات المقيدة أو مع إعدادات NAT معينة؛ مفيش TURN relay احتياطي. لو الاتصال ما ظبطش، جرّبوا شبكة تانية أو العبوا على جهاز واحد.
- كود الغرفة قصير ومش وسيلة خصوصية قوية؛ شاركوا اللينك مع أصحابكم بس. وضع الأونلاين مناسب للعب بين أصحاب، مش لمسابقات بجوايز.
- الماستر لازم يفضل فاتح الصفحة طول الجولة. لو خرج أو فقد الاتصال، الجولة ممكن تقف. مفيش نقل تلقائي للماستر ولا تنظيف تلقائي للغرف في خادم الإشارات.

## النشر

للتجربة المحلية، ابنِ الواجهة واعرضها بالأوامر دي:

```bash
npm run build
npm run preview
```

### Netlify وVercel وGitHub Pages

المنصات دي تقدر تستضيف الواجهة كملفات ثابتة، لكن زر المطابقة العشوائية محتاج خادمًا شغالًا؛ استخدم إعداد Render بالأسفل عشان الموقع والمطابقة يشتغلوا مع بعض.

### Render (الموقع والمطابقة معًا)

GitHub Pages بيستضيف ملفات الواجهة بس، ومايقدرش يشغّل خادم المطابقة. عشان تشتغل المطابقة بعد الرفع، استخدم Render كمكان واحد للموقع والخادم:

1. في Render اختار **New → Blueprint**، واربط مستودع `islam202/room-game`.
2. وافق على إعداد `render.yaml` واضغط **Apply**. ملف الإعداد بيبني الموقع ويشغّل خادم المطابقة مع بعض، ومش محتاج تدخل رابط خادم أو تضيف متغيرات يدويًا.
3. بعد ما الحالة تبقى **Live**، افتح رابط Render الظاهر عندك؛ ده رابط الموقع اللي فيه المطابقة العشوائية.
4. بعد كده كل push للتغييرات على فرع `main` بيعمل نشر تلقائي على Render. مش محتاج تشغّل `npm run dev:server` على جهازك.

رابط GitHub Pages يفضل نسخة ملفات ثابتة ومش هتدعم المطابقة. شارك رابط Render بدلًا منه. الخطة المجانية في Render ممكن توقف الخدمة بعد فترة خمول، وأول زيارة بعدها قد تتأخر؛ لو محتاجها شغالة طول الوقت استخدم خطة Web Service لا تدخل في وضع السكون.

## الأوفلاين وPWA

وضع الجهاز الواحد يشتغل أوفلاين بعد أول تحميل إنتاجي ناجح. الغرف الأونلاين محتاجة إنترنت. الـ Service Worker بيخزن التطبيق وملفاته من نفس النطاق؛ خط Google ممكن مايبقاش متاح أوفلاين وساعتها يظهر الخط البديل. وضع التطوير ما بيسجلش Service Worker.

## افتراضات وحاجات مؤجلة

- PeerJS signaling العام مجاني وسهل للتجربة، لكن الخدمة مش مضمونة كخدمة إنتاجية، وسياسة استخدامها أو إتاحتها ممكن تتغير.
- إجابة الصح مخفية عن اللاعبين العاديين وبتفضل عند الماستر في ذاكرة المتصفح، لكن الماستر يقدر يغش أو يوقف الجولة؛ مفيش خادم موثوق.
- لا دردشة، ولا حسابات أو أسماء دائمة، ولا استعادة جولة بعد إغلاق تبويب الماستر.
- مفيش relay للشبكات اللي ما بتسمحش باتصال WebRTC مباشر.
