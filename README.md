# خطفها

لعبة سرعة ورد فعل بالمصري بـ React 18 وVite. فيها لعب على جهاز واحد، وغرف أونلاين من غير إعداد Firebase أو كتابة مفاتيح. الغرف بتستخدم PeerJS/WebRTC واتصال مباشر بين المتصفحات، والماستر بيدير الجولة.

## خطة التنفيذ في ١٠ سطور

1. إعداد React 18 وVite وTailwind CSS.
2. فصل قواعد الجولة المحلية في reducer مستقل.
3. تجهيز ٦٠ سؤالًا مصريًا في `src/questions.js`.
4. إضافة شاشة بداية وإعداد أسماء اللاعبين.
5. جعل وقت السؤال الافتراضي ١٢ ثانية، مع اختيارات من ٨ لـ٢٠ ثانية.
6. تسجيل إجابات الجهاز الواحد بـ Pointer Events و`performance.now()`.
7. إنشاء غرف بكود ٤ أرقام ورابط دعوة قابل للإرسال.
8. ربط الماستر واللاعبين عبر PeerJS وWebRTC.
9. مزامنة الجولة والنقاط من الماستر، وترتيب الإجابات حسب وقت وصولها عنده.
10. تجهيز PWA والنشر كملفات ثابتة.

## التشغيل

محتاج Node.js وnpm على جهاز التطوير بس:

```bash
npm install
npm run dev
```

افتح الرابط اللي يظهر في التيرمنال. اللعب على جهاز واحد مش محتاج إعدادات خارجية. للغرف الأونلاين اضغط «العب أونلاين»، اكتب اسمك، وبعدها اعمل غرفة أو ادخل بكودها. الماستر يشارك اللينك، يستنى أصحابه، وبعدين يبدأ الجولة.

مافيش حساب Firebase أو متغيرات `.env` أو قواعد لازم تجهزها. محتاجين إنترنت عشان خدمة الإشارات العامة واتصال WebRTC يشتغلوا.

## وقت اللعب والنقاط

- من ٢ لـ٦ لاعبين، وأسماء مستعارة لحد ١٢ حرف. كل جولة ١٠ أسئلة.
- الوقت الافتراضي ١٢ ثانية للسؤال. الماستر يقدر يختار ٨ أو ١٢ أو ١٥ أو ٢٠ ثانية قبل فتح الغرفة، والوضع المحلي فيه نفس الاختيارات.
- الصح بالترتيب: ١٠ نقاط للأسرع، ثم ٦، ثم ٤، وبعدها ٢ لكل إجابة صح. الغلط يخصم ٣ نقاط ويقفل اللاعب في السؤال.
- في اللعب المحلي التوقيت مبني على `performance.now()`. أونلاين، الماستر بيسجل وقت وصول كل إجابة بساعته الرتيبة ويحسب النقاط.
- حالة الجولة مش بتتحفظ في `localStorage`؛ أسماء لاعبي الجهاز الواحد وإعداد كتم الصوت بس.

## إزاي الغرف الأونلاين شغالة؟

- الماستر بيحجز Peer ID مكوّن من بادئة اللعبة وكود ٤ أرقام من خادم PeerJS العام، واللاعب يدخل باستخدام الكود أو اللينك.
- بيانات اللعبة بتتنقل مباشرة بين أجهزة اللاعبين بتقنية WebRTC. PeerJS العام دوره خادم إشارات لتوصيل الأجهزة ببعض، مش خادم جولات أو قاعدة بيانات.
- الماستر هو اللي يوزع الأسئلة ويحسب النتيجة ويبعت تحديثات الجولة لباقي اللاعبين.
- مفيش Firebase Server Timestamp في النسخة دي. الترتيب حسب وقت وصول الإجابة عند الماستر؛ سرعة الشبكة ممكن تأثر على مين يتسجل الأول، ومفيش تحقق موثوق من ساعة كل لاعب.
- الاتصال المباشر ممكن يفشل على بعض الشبكات المقيدة أو مع إعدادات NAT معينة؛ مفيش TURN relay احتياطي. لو الاتصال ما ظبطش، جرّبوا شبكة تانية أو العبوا على جهاز واحد.
- كود الغرفة قصير ومش وسيلة خصوصية قوية؛ شاركوا اللينك مع أصحابكم بس. وضع الأونلاين مناسب للعب بين أصحاب، مش لمسابقات بجوايز.
- الماستر لازم يفضل فاتح الصفحة طول الجولة. لو خرج أو فقد الاتصال، الجولة ممكن تقف. مفيش نقل تلقائي للماستر ولا تنظيف تلقائي للغرف في خادم الإشارات.

## النشر

المشروع بيتبني لملفات ثابتة في `dist/` ومش محتاج Backend أو إعدادات خاصة:

```bash
npm run build
npm run preview
```

### Netlify

- Build command: `npm run build`
- Publish directory: `dist`

### Vercel

- Build command: `npm run build`
- Output directory: `dist`

### GitHub Pages

استخدم GitHub Actions لتشغيل `npm ci` وبعدها `npm run build` ونشر محتوى `dist/`. إعداد `base: './'` في Vite بيدعم النشر داخل مسار المستودع. تثبيت PWA محتاج HTTPS.

## الأوفلاين وPWA

وضع الجهاز الواحد يشتغل أوفلاين بعد أول تحميل إنتاجي ناجح. الغرف الأونلاين محتاجة إنترنت. الـ Service Worker بيخزن التطبيق وملفاته من نفس النطاق؛ خط Google ممكن مايبقاش متاح أوفلاين وساعتها يظهر الخط البديل. وضع التطوير ما بيسجلش Service Worker.

## افتراضات وحاجات مؤجلة

- PeerJS signaling العام مجاني وسهل للتجربة، لكن الخدمة مش مضمونة كخدمة إنتاجية، وسياسة استخدامها أو إتاحتها ممكن تتغير.
- إجابة الصح مخفية عن اللاعبين العاديين وبتفضل عند الماستر في ذاكرة المتصفح، لكن الماستر يقدر يغش أو يوقف الجولة؛ مفيش خادم موثوق.
- لا دردشة، ولا حسابات أو أسماء دائمة، ولا استعادة جولة بعد إغلاق تبويب الماستر.
- مفيش relay للشبكات اللي ما بتسمحش باتصال WebRTC مباشر.
